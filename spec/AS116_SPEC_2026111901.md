# 1　はじめに

## 1.1 AS116について
AS116は、AkidukiSystemsが開発する16bit命令セット・アーキテクチャである。AS16とアセンブリ言語の構文に一部互換性を持ち、命令コードのサイズ削減および最適化を目的として設計されている。

## 1.2 開発目的
AS116は、AS16が抱える命令コードサイズの肥大化という問題を解消するために策定された。

## 1.3 AS16との関係
AS116はAS16と機械語レベルでの互換性を持たない。一方、命令の動作、レジスタ構成およびメモリアドレッシングについては、AS16との後方互換性を考慮して設計されている。

## 1.4 Intel 8086との関係
AS116はAS16と同様に、Intel 8086との機械語互換性を持たない。一方、一部の命令の動作、レジスタ構成およびメモリアドレッシングについては、Intel 8086と同等の動作をする。

## 1.5 仕様書の適用範囲
本書では、AS116命令セット・アーキテクチャにおける命令の動作、レジスタ、メモリアドレッシング、スタック操作、フラグ管理、割込み、例外、入出力、メモリマップおよびリセット動作について規定する。

なお、アセンブラ、マイクロアーキテクチャ、BIOSおよびDOSの実装詳細については、本書の規定対象外とする。

## 1.6 用語定義

### 1.6.1 例外
| 表記 | 説明 |
|---|---:|
| #DE | 除算エラー例外（INT 00h）|
| #UD | 無効命令例外（INT 06h）|

## 1.7 表記規則
本書では、特に明示されない限り、数値は10進数で表記する。
16進数は、以下のいずれかの形式で表記する。

- `0x` に続けて16進数を記述する形式
- 数値の末尾に `h` または `H` を付加する形式
- 文脈上、16進数であることが明らかな場合の数値単独表記

16進数の表記には、`0`～`9` および `A`～`F` の16種類の文字を使用する。

# 2　プロセッサ概要

## 2.1 アーキテクチャ概要
AS116は、8bitおよび16bitのデータを扱う16bit命令セット・アーキテクチャである。
AS116は、セグメント方式によるメモリアドレッシングを採用し、メモリ空間と入出力空間を独立して管理する。
命令形式にはType-A、Type-B、Type-Cの3種類が存在する。

## 2.2 データ幅
AS116命令セット・アーキテクチャでは、バイト、ワードの2種類を基本データ型として定義する。
各データ型のサイズは以下のとおりである。
| データ型 | サイズ | 略式記号
|---|---|---:|
| バイト（Byte） | 8bit | BYTE |
| ワード（Word） | 16bit | WORD |

### 2.2.1 数値データ型
AS116では、基本データ型を用いて、以下の数値データ型を定義する。
- 符号なしバイト整数
- 符号ありバイト整数
- 符号なしワード整数
- 符号ありワード整数

## 2.3 エンディアン
AS116のエンディアンはリトルエンディアンである。

## 2.4 メモリアーキテクチャ
AS116は、セグメント方式によるメモリアドレッシングを採用する。
メモリアドレスは、16bitのセグメントセレクタと16bitのオフセット値によって構成され、次の形式で表される。
- Segment:Offset

物理アドレスは、セグメントセレクタを4bit左シフトした値にオフセット値を加算することで算出される。
演算式は次のとおりである。
- PhysicalAddress = Segment × 10h + Offset

AS116は、メモリ空間とは独立した入出力空間を持つ。入出力空間へのアクセスには、専用命令であるINおよびOUTを使用する。

## 2.5 レジスタ構成
AS116は、以下のレジスタを備える。
- 汎用レジスタ
- セグメントレジスタ
- フラグレジスタ
- 命令ポインタレジスタ

### 2.5.1 汎用レジスタ
AS116には、8本の16bitレジスタ（AX、BX、CX、DX、SI、DI、BP、SP）が搭載されている。
このうち、AX、BX、CX、DXは汎用レジスタ、SI、DI、BP、SPはポインタ・インデックスレジスタとして分類される。
これらのレジスタは、以下の用途に使用される。
- 論理演算および算術演算用のオペランド
- アドレス計算用のオペランド
- メモリポインタ

これらのレジスタはいずれも、演算結果やポインタなどを保持する汎用記憶領域として使用できる。
SPレジスタはスタックポインタとして使用することを推奨する。ただし、他の用途への使用をCPUが制限するものではない。

### 2.5.2 セグメントレジスタ
セグメントレジスタ（CS、DS、SS、ES）は、16bitのセグメントセレクタを保持する。
セグメントセレクタは、メモリ内のセグメントを識別するための値である。
メモリ内の特定のセグメントにアクセスするには、そのセグメントに対応するセグメントセレクタが、適切なセグメントレジスタに格納されていなければならない。

### 2.5.3 フラグレジスタ
16bitのフラグレジスタには、論理演算や算術演算などによって更新されるステータスフラグが格納される。
フラグレジスタに含まれる一部のフラグは、専用命令によって直接変更できる。

### 2.5.4 命令ポインタレジスタ
命令ポインタレジスタ（IP）は、現在のコードセグメント内における次に実行する命令のオフセットを保持する。
通常の命令実行では、IPは命令の長さに応じて次の命令位置へ進められる。
一方、JMP、Jcc、JCXZ、JF、CALL、RET、CALLF、FRET、IRET、LOOP、LOOPZ、LOOPNZなどの制御移行命令を実行した場合、IPはそれぞれの命令の動作に従って変更される。

## 2.6 命令セット概要
AS116の命令は、命令形式によってType-A、Type-B、Type-Cの3種類に分類される。
各命令形式は、それぞれ異なる命令ヘッダ構造を持ち、命令の種類やオペランドの指定方法を定義する。
各命令形式については第4章、命令IDについては第5章、各命令の詳細については第6章で規定する。

## 2.7 アドレス空間
AS116は、メモリ空間と入出力空間を独立して管理する。
それぞれのアドレス空間は以下の範囲を持つ。
| アドレス空間 | アドレス範囲 |
|---|---|
| メモリ空間 | 00000000h ～ 0010FFEFh |
| 入出力空間 | 0000h ～ FFFFh |

メモリ空間へのアクセスにはメモリアドレッシングを使用し、入出力空間へのアクセスにはINおよびOUT命令を使用する。
メモリ空間の具体的な配置については、第12章で規定する。

## 2.8 割り込み・例外概要
AS116は、割り込みおよび例外処理機構を備える。
割り込み処理には、INT命令によるソフトウェア割り込みと、外部要因によって発生するハードウェア割り込みが存在する。
また、CPUの実行中に特定の条件が発生した場合、例外が発生する。
割り込みおよび例外の処理には、割り込みベクタテーブル（IVT）を使用する。IVTは物理アドレス00000000hから000003FFhまでの領域に配置され、256個の割り込みベクタを保持する。
割り込みおよび例外の詳細については、第9章および第10章で規定する。

## 2.9 予約領域
命令フォーマット及びレジスタ識別子内の予約ビットフィールド（Reservedフィールド）は、将来の拡張などのために確保された予約領域である。
本書では多くの箇所で予約領域が登場する。
予約領域の取り扱いは以下のとおり。
- アセンブラは予約領域を必ず0として出力する。
- 命令実行時には予約領域をマスキングし、その値を無視する。
予約領域の値が0以外であっても、それ自体を理由として例外は発生しない。
なお、予約領域と未定義命令は異なる。未定義命令を実行した場合は#UDを発生させる。

# 3　レジスタ仕様

## 3.1 レジスタ概要
AS116では、汎用レジスタ、セグメントレジスタ、命令ポインタ（IP）、フラグレジスタ（FLAGS）を使用する。
各レジスタの構成は以下のとおり。
| 分類 | レジスタ | ビット幅 |
|---|---|---:|
| 汎用レジスタ | AX、BX、CX、DX | 16bit |
| ポインタ・インデックスレジスタ | SI、DI、BP、SP | 16bit |
| セグメントレジスタ | CS、DS、ES、SS | 16bit |
| 命令ポインタ | IP | 16bit |
| フラグレジスタ | FLAGS | 16bit |

AX、BX、CX、DXは、それぞれ上位8bitと下位8bitを独立したレジスタとして扱うことができる。
IPおよびFLAGSは、通常の命令オペランドとして使用するレジスタには含まれない。

## 3.2 汎用レジスタ
AS116には、AX、BX、CX、DXの4つの汎用レジスタが存在する。
各レジスタのビット幅は16bitであり、上位8bitと下位8bitを個別に操作できる。
| 16bitレジスタ | 上位8bit | 下位8bit |
|---|---|---|
| AX | AH | AL |
| BX | BH | BL |
| CX | CH | CL |
| DX | DH | DL |

各レジスタは、演算、論理演算、データの一時保存など、汎用的な用途に使用する。
16bitレジスタと対応する8bitレジスタは同一のレジスタ領域を共有する。したがって、上位8bitまたは下位8bitへの書き込みは、対応する16bitレジスタの一部に反映される。
例えば、ALへの書き込みはAXの下位8bitに反映され、AHへの書き込みはAXの上位8bitに反映される。

## 3.3 ポインタ・インデックスレジスタ
AS116には、SI、DI、BP、SPの4つのポインタ・インデックスレジスタが存在する。
各レジスタのビット幅は16bitである。
| レジスタ | 用途 |
|---|---|
| SI | インデックスレジスタ |
| DI | インデックスレジスタ |
| BP | ベースポインタ |
| SP | スタックポインタ |

これらのレジスタは、メモリアドレスの指定やデータの参照などに使用する。
これらのレジスタは、レジスタ間の役割に基づく名称を持つが、特定の用途にCPUによって制限されるものではない。

## 3.4 セグメントレジスタ
AS116には、CS、DS、ES、SSの4つのセグメントレジスタが存在する。
各レジスタのビット幅は16bitであり、メモリアドレスを構成するセグメントセレクタを保持する。
| レジスタ | 用途 |
|---|---|
| CS | コードセグメント |
| DS | データセグメント |
| ES | エクストラセグメント |
| SS | スタックセグメント |

メモリアクセス時には、対象となる処理に応じて適切なセグメントレジスタが使用される。
基本的なセグメントの選択規則は以下のとおり。
| アクセス対象 | 使用するセグメントレジスタ |
|---|---|
| 命令フェッチ | CS |
| 通常のメモリアクセス | DS |
| スタック操作 | SS |

セグメントセレクタとオフセットから物理アドレスを算出する方法については、第7章を参照する。

## 3.5 命令ポインタ（IP）
IPは、現在のコードセグメント内における命令のオフセットを保持する16bitレジスタである。
命令フェッチ時にはCSとIPを組み合わせて命令の物理アドレスを算出する。
通常の命令実行では、命令の読み込みに伴ってIPが更新される。
分岐命令、サブルーチン呼び出し、復帰命令、割り込み処理などでは、それぞれの命令仕様に従ってIPが変更される。
各命令によるIPの更新動作については、第6章、割り込み処理については第9章を参照する。

## 3.6 フラグレジスタ（FLAGS）
FLAGSは、CPUの演算結果や実行状態を保持する16bitレジスタである。
AS116では、Intel 8086と互換性のある以下のフラグを使用する。
| ビット位置 | フラグ | 名称 | 概要 |
|---:|---|---|---|
| 0 | CF | Carry Flag | キャリーフラグ |
| 2 | PF | Parity Flag | パリティフラグ |
| 4 | AF | Auxiliary Carry Flag | 補助キャリーフラグ |
| 6 | ZF | Zero Flag | ゼロフラグ |
| 7 | SF | Sign Flag | サインフラグ |
| 8 | TF | Trap Flag | トラップフラグ |
| 9 | IF | Interrupt Flag | 割り込み許可フラグ |
| 10 | DF | Direction Flag | ディレクションフラグ |
| 11 | OF | Overflow Flag | オーバーフローフラグ |

各フラグの具体的な更新条件および操作方法は、第6章を参照する。
割り込み許可状態など、FLAGSの値が割り込み処理に与える影響については、第9章を参照する。

## 3.7 レジスタ識別子
命令のオペランドとしてレジスタを指定する場合、8bitのレジスタ識別子を使用する。
レジスタ識別子は以下の構成を持つ。
| フィールド | ビット幅 | 説明 |
|---|---:|---|
| ビット幅指定フラグ | 1bit | レジスタのビット幅 |
| 上位・下位指定フラグ | 1bit | ビット幅が8bitの場合の上位・下位レジスタの指定 |
| レジスタID | 4bit | レジスタの識別番号 |
| Reserved | 1bit | 予約領域 |
| 繰返し指定フラグ | 1bit | レジスタ識別子の省略指定 |

### 3.7.1 ビット幅指定フラグ
レジスタのビット幅を指定する。
| 値 | ビット幅 |
|---:|---:|
| 0 | 8bit |
| 1 | 16bit |

### 3.7.2 上位・下位指定フラグ
8bitレジスタを指定する場合に、上位・下位のどちらを使用するか指定する。
| 値 | 指定 |
|---:|---|
| 0 | 下位8bit |
| 1 | 上位8bit |

ビット幅指定フラグが1の場合、上位・下位指定フラグは必ず0とする。ビット幅指定フラグが1かつ上位・下位指定フラグが1の組み合わせは無効である。

### 3.7.3 レジスタID
レジスタを識別するための4bitの番号である。
各IDと対応するレジスタは以下のとおり。
| レジスタID | 16bitレジスタ | 下位8bit | 上位8bit |
|---:|---|---|---|
| 0 | AX | AL | AH |
| 1 | BX | BL | BH |
| 2 | CX | CL | CH |
| 3 | DX | DL | DH |
| 4 | SI | - | - |
| 5 | DI | - | - |
| 6 | BP | - | - |
| 7 | SP | - | - |
| 8 | CS | - | - |
| 9 | DS | - | - |
| 10 | ES | - | - |
| 11 | SS | - | - |
| 12～15 | Reserved | - | - |

レジスタIDが12～15の場合は無効なレジスタ指定として扱い、#UDを発生させる。
SI、DI、BP、SPおよびセグメントレジスタは16bitでのみ指定できる。これらのレジスタを8bitとして指定した場合は、無効なレジスタ指定として#UDを発生させる。

### 3.7.4 繰返し指定フラグ
後続のオペランドで同一のレジスタを再指定する場合に、2つ目のレジスタ識別子を省略するための指定である。
| 値 | 動作 |
|---:|---|
| 0 | 通常のレジスタ指定 |
| 1 | 2つ目のレジスタ識別子を省略 |

繰返し指定フラグを使用できるのは、Type-A命令において、第1オペランドと第2オペランドがともにREGであり、両者が同一のレジスタを指定する場合に限る。
繰返し指定フラグを使用した場合、第1オペランドのレジスタ識別子に繰返し指定フラグを設定し、第2オペランドのレジスタ識別子を省略する。
例えば、以下の命令では同一レジスタを2回指定している。
```asm
XOR AX, AX
```

繰返し指定フラグを使用することで、2つ目のレジスタ識別子を省略できる。
```
10 09 81
```

繰返し指定フラグの使用条件に反する指定は、AS116の命令仕様上認められない。AS116は繰返し指定フラグの不正使用を検知できないため、意図しない動作を引き起こす恐れがある。

## 3.8 レジスタ識別子の例
代表的なレジスタ識別子を以下に示す。
| レジスタ | 識別子 |
|---|---:|
| AX | 80h |
| AH | 40h |
| AL | 00h |
| BX | 84h |
| BH | 44h |
| BL | 04h |
| SI | 90h |
| DI | 94h |
| BP | 98h |
| SP | 9Ch |
| CS | A0h |
| DS | A4h |
| ES | A8h |
| SS | ACh |

上記の値は予約領域および繰返し指定フラグを0とした場合のレジスタ識別子である。

# 4　命令フォーマット

## 4.1 命令フォーマット概要
AS116の命令は、Type-A、Type-B、Type-Cの3種類の形式で構成される。
各命令形式は、命令の種類やオペランドの指定方法に応じて異なるビット構成を持つ。
| 命令形式 | ヘッダサイズ | 主な用途 |
|---|---:|---|
| Type-A | 16bit | 2つのオペランドを持つ命令 |
| Type-B | 16bit | 1つのオペランドを持つ命令 |
| Type-C | 8bit | オペランドを持たない命令 |

命令はヘッダとオペランドデータから構成される。オペランドデータの有無およびサイズは、命令形式や各フィールドの指定によって決定される。
各命令形式の識別には、ヘッダ先頭の命令形式識別子（MK）を使用する。

## 4.2 命令形式識別子（MK）
MKは、命令形式を識別するための2bitのフィールドである。
| MK | 命令形式 |
|---|---|
| 00 | Type-A |
| 01 | Type-B |
| 10 | Type-C |
| 11 | 未定義 |

MKが11の場合、その命令は未定義命令として扱い、#UDを発生させる。

## 4.3 Type-A命令フォーマット
Type-Aは、2つのオペランドを持つ命令に使用する形式である。
ヘッダサイズは16bitであり、以下の構成を持つ。
```text
15 14 13    8      7 6      5    4 3   2 1   0
+----+-------+------+--------+----+-----+-----+
| MK |  MID  | IMM8 |Reserved| DL | OA1 | OA2 |
+----+-------+------+--------+----+-----+-----+
 2bit 6bit    1bit   2bit     1bit 2bit  2bit
```

各フィールドの詳細については、4.6節を参照する。

## 4.4 Type-B命令フォーマット
Type-Bは、1つのオペランドを持つ命令に使用する形式である。
ヘッダサイズは16bitであり、以下の構成を持つ。
```text
15 14 13    8 7                  3    2 1   0
+----+-------+--------------------+----+-----+
| MK |  MID  | Jcc Type / Reserved| DL | OA1 |
+----+-------+--------------------+----+-----+
 2bit 6bit    5bit                 1bit 2bit
```

Jcc命令では、Jcc Typeフィールドを条件コードとして使用する。それ以外の命令では、同じ領域を予約領域として扱う。
各フィールドの詳細については、4.6節を参照する。

## 4.5 Type-C命令フォーマット
Type-Cは、オペランドを持たない命令に使用する形式である。
ヘッダサイズは8bitであり、以下の構成を持つ。
```text
7            6 5                       0
+-------------+-------------------------+
|     MK      |           MID           |
+-------------+-------------------------+
     2bit                 6bit
```

Type-Cには、オペランド属性やデータ長を指定するフィールドは存在しない。

## 4.6 フィールド仕様
各命令形式で使用するフィールドの意味および動作を以下に示す。

### 4.6.1 MID
MIDは、命令の種類を識別するための6bitのフィールドである。
同じMIDであっても、命令形式によって意味が異なる場合がある。
各命令形式におけるMIDの割り当てについては、第5章を参照する。

### 4.6.2 IMM8
IMM8は、Type-A命令において、即値データを8bitで格納するかどうかを指定する1bitのフィールドである。
| 値 | 動作 |
|---|---|
| 0 | 即値をDLに対応するビット幅で格納する |
| 1 | すべての即値を8bitで格納する |

IMM8を1とする条件は、命令内に存在するすべての即値が符号なし8bit整数の範囲（0～255）に収まることである。
命令内に即値が存在しない場合、または1つでも範囲外の即値が存在する場合は、IMM8を0とする。
IMM8は命令単位で適用されるため、複数の即値が存在する場合も、すべての即値に同じ指定が適用される。
DLが1かつIMM8が1の場合、即値は8bitで格納され、上位8bitはすべて0として扱う。
例えば、DLが1で即値が100の場合、即値データは64hとして格納され、16bitの値としては0064hとなる。

### 4.6.3 DL
DLは、命令で扱うデータのビット幅を指定するフィールドである。
| DL | データ幅 |
|---|---|
| 0 | 8bit |
| 1 | 16bit |

DLは、命令の種類に応じて対象となるデータのビット幅を決定する。
IN命令では読み込みデータのビット幅、OUT命令では出力データのビット幅を指定する。
その他の命令におけるDLの適用対象は、各命令の仕様に従う。

### 4.6.4 OA（OA1・OA2）
OAは、オペランドの属性を指定する2bitのフィールドである。
Type-Aでは第1オペランドをOA1、第2オペランドをOA2で指定する。Type-Bでは第1オペランドをOA1で指定する。
| OA | 属性 | 説明 |
|---|---|---|
| 00 | REG | レジスタ |
| 01 | MEM | 直接メモリアドレス |
| 10 | IMM | 即値 |
| 11 | REGIND | レジスタ間接メモリ |

REGは、レジスタ識別子によって指定されたレジスタを表す。
MEMは、直接指定されたメモリアドレスを表す。
IMMは、命令内に格納された即値を表す。
REGINDは、レジスタに格納されたアドレスを使用するメモリオペランドを表す。例えば、`[DX]`のような指定が該当する。
Type-Aでは、OA1とOA2の組み合わせに制限を設けない。

## 4.6.5 Jcc Type
Jcc Typeは、Type-Bの条件分岐命令（Jcc）において使用する5bitの条件コードである。
Jcc Typeの各値と対応するニーモニックおよび条件については、第5章を参照する。

## 4.7 オペランドデータの配置
Type-AおよびType-Bでは、ヘッダの後にオペランドデータを配置する。
Type-Aでは、第1オペランド、第2オペランドの順にデータを格納する。Type-Bでは、第1オペランドに対応するデータを格納する。
オペランドに対応するデータ形式および格納サイズは以下のとおり。
| 属性 | 格納するデータ | 格納サイズ |
|---|---|---:|
| REG | レジスタ識別子 | 8bit |
| MEM | 直接メモリアドレス | 16bit |
| IMM | 即値 | IMM8およびDLに依存 |
| REGIND | レジスタ識別子 | 8bit |

REGおよびREGINDで使用するレジスタ識別子のビット構成については、第3章を参照する。
MEMで指定するメモリアドレスは16bitのオフセット値である。DLが指定するデータ幅とは独立している。
メモリアドレスおよび複数バイトの即値はリトルエンディアンで格納する。
即値の格納サイズは命令形式によって異なる。
- Type-A：IMM8が1の場合は8bit、0の場合はDLに対応するビット幅で格納する。
- Type-B：DLに対応するビット幅で格納する。

Type-Cはオペランドを持たないため、ヘッダのみで命令が構成される。
具体的な命令ごとのオペランド構成および実行動作については、第6章を参照する。

## MOV
### 命令コード一覧
MOVはType-A命令、MID=000000bを使用する。
| Type | MID | OA1 | OA2 | 命令形式 | 機械語(8bit) | 機械語(16bit) (,IMM8=1) |
|---|---|---|---|---|---|---|
| A | 000000b | 00b | 00b | MOV REG, REG | 00 00 | 10 00 |
| A | 000000b | 00b | 01b | MOV REG, MEM | 01 00 | 11 00 |
| A | 000000b | 00b | 10b | MOV REG, IMM | 02 00 | 12 00, 92 00 |
| A | 000000b | 00b | 11b | MOV REG, REGIND | 03 00 | 13 00 |
| A | 000000b | 01b | 00b | MOV MEM, REG | 04 00 | 14 00 |
| A | 000000b | 01b | 01b | MOV MEM, MEM | 05 00 | 15 00 |
| A | 000000b | 01b | 10b | MOV MEM, IMM | 06 00 | 16 00, 96 00 |
| A | 000000b | 01b | 11b | MOV MEM, REGIND | 07 00 | 17 00 |
| A | 000000b | 11b | 00b | MOV REGIND, REG | 0C 00 | 1C 00 |
| A | 000000b | 11b | 01b | MOV REGIND, MEM | 0D 00 | 1D 00 |
| A | 000000b | 11b | 10b | MOV REGIND, IMM | 0E 00 | 1E 00, 9E 00 |
| A | 000000b | 11b | 11b | MOV REGIND, REGIND | 0F 00 | 1F 00 |

共通フィールドは以下のとおり。
| フィールド | 設定 |
|---|---|
| MK | 00b |
| MID | 000000b |
| IMM8 | 第4章の即値符号化規則に従う |
| Reserved | 00b |
| DL | 0：8bit、1：16bit |
| OA1 | 転送先のオペランド形式 |
| OA2 | 転送元のオペランド形式 |

OA1にはREG、MEM、REGINDを指定できる。IMMは転送先として指定できない。

### 説明
転送元オペランドSRCの値を、転送先オペランドDESTへ転送する。
転送元の値は変更されない。
転送先と転送元には、レジスタ、メモリ、即値を指定できる。ただし、即値は転送元に限る。
メモリ間転送を許可する。転送先と転送元の両方にMEMまたはREGINDを指定できる。
セグメントレジスタも通常のレジスタオペランドとして使用できる。CSを含むすべてのセグメントレジスタについて、転送元および転送先の両方に指定できる。
オペランドのデータ幅はDLによって決定する。レジスタオペランドのデータ幅はDLと一致していなければならない。
セグメントレジスタは16bitであるため、DL=1の場合に限り使用できる。
MEMおよびREGINDによるメモリアクセスのセグメントレジスタにはDSを使用する。メモリアクセスの詳細は第7章に従う。
即値の符号化および上位ビットの扱いは、第4章のIMM8規則に従う。DL=1かつIMM8=1の場合、即値の上位8bitは0で埋める。

### 動作
```text
DEST ← SRC;
```

| CF | - |
| PF | - |
| AF | - |
| ZF | - |
| SF | - |
| TF | - |
| IF | - |
| DF | - |
| OF | - |

### 説明
第一オペランドDESTから第二オペランドSRCを減算し、その結果をDESTに格納する。
演算対象には、レジスタ、メモリ、即値を指定できる。ただし、即値は第二オペランドに限る。
メモリ間演算を許可する。両オペランドにMEMまたはREGINDを指定できる。
オペランドのデータ幅はDLによって決定する。両オペランドのデータ幅は一致していなければならない。レジスタオペランドのデータ幅はDLと一致していなければならない。
REGおよびREGINDでは、セグメントレジスタを指定することはできない。指定した場合、#UD例外を発生する。
MEMおよびREGINDによるメモリアクセスのセグメントレジスタにはDSを使用する。メモリアクセスの詳細は第7章に従う。
即値の符号化および上位ビットの扱いは、第4章のIMM8規則に従う。DL=1かつIMM8=1の場合、即値の上位8bitは0で埋める。

### 動作
```text
DEST ← DEST - SRC;
testFlags(DEST, CF||PF||AF||ZF||SF||OF);
```

### フラグへの影響
OF、SF、ZF、AF、PF、CFは演算結果に応じて変更される。
| フラグ | 動作 |
|---|---|
| CF | 結果に応じて変更 |
| PF | 結果に応じて変更 |
| AF | 結果に応じて変更 |
| ZF | 結果に応じて変更 |
| SF | 結果に応じて変更 |
| TF | - |
| IF | - |
| DF | - |
| OF | 結果に応じて変更 |

### 例外
**#UD（Invalid Opcode）**
第10.4節の条件によって発生する。

# 7　メモリアドレッシング

## 7.1 メモリアドレッシング概要
AS116は、セグメント方式によるメモリアドレッシングを採用する。
メモリアドレスは、16bitのセグメントセレクタと16bitのオフセット値によって構成される。
AS116では、以下の2種類のメモリアドレッシング方式を使用する。
- 直接メモリアドレッシング
- レジスタ間接メモリアドレッシング

メモリオペランドの指定には、命令フォーマットで定義されたMEMまたはREGINDを使用する。

## 7.2 物理アドレスの算出
AS116では、セグメントセレクタとオフセット値から物理アドレスを算出する。
物理アドレスの算出式は以下のとおり。
```text
PhysicalAddress = Segment × 10h + Offset
```

セグメントセレクタを4bit左シフトし、その値にオフセット値を加算することで物理アドレスを得る。
例えば、セグメントセレクタが1234h、オフセット値が5678hの場合、物理アドレスは以下のようになる。
```text
1234h × 10h + 5678h
= 12340h + 5678h
= 179B8h
```

AS116では、物理アドレスの算出結果を20bitに切り詰めない。
したがって、物理アドレスの最大値は以下のとおりとなる。
```text
FFFFh × 10h + FFFFh = 0010FFEFh
```

AS116で生成可能な物理アドレスの範囲は00000000hから0010FFEFhまでである。

## 7.3 直接メモリアドレッシング
直接メモリアドレッシングは、命令内に格納された16bitのオフセット値によってメモリアドレスを指定する方式である。
命令フォーマットにおけるMEM属性が該当する。
指定されたオフセット値と、セグメント選択規則に従って選択されたセグメントレジスタの値を組み合わせて、物理アドレスを算出する。
以下に使用例を示す。
```asm
MOV AX, [1234h]
```

この場合、1234hをオフセット値として使用する。物理アドレスは以下の式で算出される。
```text
PhysicalAddress = Segment × 10h + 1234h
```

MEM属性で指定するアドレスは16bitのオフセット値であり、データのビット幅とは独立している。

## 7.4 レジスタ間接メモリアドレッシング
レジスタ間接メモリアドレッシングは、レジスタに保持された値をオフセット値として使用する方式である。
命令フォーマットにおけるREGIND属性が該当する。
レジスタ識別子によって指定されたレジスタの値を使用し、セグメント選択規則に従って選択されたセグメントレジスタの値と組み合わせて物理アドレスを算出する。
以下に使用例を示す。
```asm
MOV AX, [DX]
```

この場合、DXに保持されている値をオフセット値として使用する。物理アドレスは以下の式で算出される。
```text
PhysicalAddress = Segment × 10h + DX
```

レジスタ間接メモリアドレッシングでは、レジスタに保持された値をそのままオフセット値として使用する。オフセット値に対する変位の加算や、複数のレジスタを組み合わせたアドレス指定は行わない。

## 7.5 セグメント選択規則
メモリアクセス時に使用するセグメントレジスタは、アクセスの種類に応じて決定する。
基本的な選択規則は以下のとおり。
| アクセス対象 | 使用するセグメントレジスタ |
|---|---|
| 命令フェッチ | CS |
| 通常のメモリアクセス | DS |
| スタック操作 | SS |

通常のメモリアクセスでは、直接メモリアドレッシングとレジスタ間接メモリアドレッシングのどちらを使用した場合も、DSを使用する。
セグメントレジスタを任意に変更するセグメントオーバーライド機能は存在しない。

## 7.6 メモリアクセス
メモリへのアクセス時には、命令のDLフィールドによってデータのビット幅を決定する。
| DL | データ幅 |
|---|---|
| 0 | 8bit |
| 1 | 16bit |

メモリアドレスとして使用するオフセット値は16bitであり、DLによるデータ幅の指定とは独立している。
16bitのメモリアクセスでは、最初のバイトを指定されたオフセット値から取得または格納し、次のバイトをオフセット値に1を加算したアドレスから取得または格納する。
このとき、オフセット値の加算結果は16bitの範囲で扱う。したがって、オフセット値がFFFFhの場合、次のバイトへのアクセスではオフセット値が0000hに折り返る。
例えば、DS:FFFFhを先頭とする16bitのメモリアクセスでは、以下のアドレスを使用する。
- 下位8bit：DS:FFFFh
- 上位8bit：DS:0000h

各バイトの物理アドレスは、同一のセグメントセレクタと、それぞれのオフセット値から個別に算出する。
メモリ上の複数バイトデータの配置順序は、第2章で定義したリトルエンディアンに従う。
なお、オフセット値の折り返しは16bitの範囲内で行うが、物理アドレスの20bitへの切り詰めは行わない。物理アドレスの算出については第7.2節の規定に従う。
メモリへの読み書きは、命令のオペランド属性および各命令の動作仕様に従って実行する。

## 7.7 メモリアクセス時の例外
メモリアクセス先の物理アドレスが、実装されているメモリの範囲外である場合、#UDを発生させる。
16bitのメモリアクセスでは、アクセス対象となる2バイトそれぞれについて物理アドレスを算出し、実装メモリの範囲内であることを確認する。
いずれか一方のバイトの物理アドレスが実装されているメモリの範囲外である場合、#UDを発生させる。
実装メモリの範囲および具体的なメモリ配置については、第12章で規定する。

# 8　スタック

## 8.1 スタック概要
AS116は、メモリ上に構築されるスタックを使用する。
スタックは、後入れ先出し（LIFO：Last In, First Out）方式でデータを管理する。
スタック操作は16bit単位で行い、データの格納および取り出しにはスタックポインタ（SP）を使用する。

## 8.2 スタックレジスタ
AS116では、スタックの管理に以下のレジスタを使用する。
| レジスタ | 役割 |
|---|---|
| SS | スタックセグメント |
| SP | スタックポインタ |

SSはスタックが配置されているセグメントを示す。
SPはスタックの先頭位置を示す16bitのオフセット値を保持する。
スタックへのアクセスには、SSとSPを組み合わせた論理アドレスを使用する。

## 8.3 スタックアドレス
スタックへのアクセスには、SS:SPによるセグメント方式のアドレス指定を使用する。
物理アドレスは第7章で定義した算出方式に従い、以下の式で求める。
```text
PhysicalAddress = SS × 10h + SP
```

スタック操作では、通常のメモリアクセスで使用するDSではなく、SSを使用する。

## 8.4 スタックの成長方向
AS116のスタックは、メモリアドレスの小さい方向へ成長する。
スタックへのデータ格納時にはSPを減算し、データの取り出し時にはSPを加算する。
PUSH命令では、SPを2減算した後、新しいSPが示すメモリアドレスに16bitのデータを格納する。
POP命令では、現在のSPが示すメモリアドレスから16bitのデータを取り出した後、SPを2加算する。
なお、PUSH SPを実行した場合、スタックに格納されるSPの値は、減算後の値となる。

## 8.5 スタックデータの配置
スタックに格納するデータは16bitのワード単位とする。
複数バイトのデータはリトルエンディアンで格納する。
16bitのデータを格納する場合、下位8bitを低位アドレスに、上位8bitを高位アドレスに配置する。

## 8.6 スタック操作のデータ幅
AS116では、スタック操作に8bitのデータ幅を使用することはできない。
PUSH命令およびPOP命令では、DLが1の場合のみ有効とする。
DLが0の場合は無効な命令指定として扱い、#UDを発生させる。
PUSHA、POPA、PUSHFおよびPOPFなど、データ幅を命令形式で指定しないスタック操作についても、16bit単位で動作する。

## 8.7 スタックの範囲と例外
SPは16bitのレジスタであり、加算および減算の結果は16bitの範囲で扱う。
したがって、SPの加算または減算によって0000hまたはFFFFhの境界を越えた場合、16bitの範囲で折り返す。
スタック専用のオーバーフローおよびアンダーフロー検出機構は設けない。
ただし、スタック操作によってアクセスした物理アドレスが実装されているメモリの範囲外である場合は、第7章の規定に従い#UDを発生させる。

# 9　割込み

## 9.1 割込み概要
割込みは、CPUが実行中の処理を中断し、指定された割込みハンドラへ制御を移すための機構である。
AS116では、ソフトウェア割込み、ハードウェア割込みおよびシングルステップ割込みを扱う。また、CPUの命令実行中に特定の条件が発生した場合は例外が発生する。
割込みおよび例外の処理には、割込みベクタテーブル（IVT）を使用する。例外の発生条件および種類については第10章を参照すること。
割込みが発生すると、CPUは現在の実行状態をスタックに保存し、割込みベクタに対応する割込みハンドラへ制御を移す。

## 9.2 割込みベクタ
割込みベクタは、割込みハンドラの実行開始位置を示す情報である。
AS116では、256個の割込みベクタを持ち、それぞれ8bitの番号で識別する。
割込みベクタテーブルは物理アドレス `00000000h` から配置され、各エントリは4バイトで構成される。
各エントリには、割込みハンドラの開始位置を示すIPおよびCSを格納する。エントリ内の格納順序は以下のとおりとする。
- オフセット +0：IP（16bit）
- オフセット +2：CS（16bit）

割込みベクタ番号を `N` とした場合、対応するエントリの物理アドレスは次の式で求められる。
`N × 4`

割込みベクタテーブルの詳細については第12章を参照すること。

## 9.3 ソフトウェア割込み
ソフトウェア割込みは、プログラムが割込み命令を実行することで発生する割込みである。
AS116では、INT、INT3およびINTOの3種類の命令によってソフトウェア割込みを発生させる。

### 9.3.1 INT命令
INT命令は、指定された割込み番号に対応するソフトウェア割込みを発生させる命令である。
割込み番号は、8bitの即値によって指定する。指定可能な範囲は00h～FFhとする。
INT命令はType-Bに属し、命令フィールドは以下の値に固定する。
| フィールド | 値 |
|---|---|
| MID | 19 |
| DL | 0 |
| OA1 | IMM(即値) |

即値には割込み番号を格納する。即値の格納サイズは8bitとする。
例えば、割込み番号10hを指定する場合、以下のアセンブリ命令となる。
```asm
INT 10h
```

この場合の機械語は以下のとおりである。
```text
02 53 10
```

INT命令を実行すると、指定された割込み番号に対応するIVTエントリを参照し、割込み処理を開始する。
INT命令による割込みでは、INT命令の次の命令のアドレスを復帰先IPとして保存する。

### 9.3.2 INT3命令
INT3命令は、割込み番号03hのソフトウェア割込みを発生させる命令である。
INT3命令はType-Cに属する。
INT3命令による割込みでは、INT3命令の次の命令のアドレスを復帰先IPとして保存する。

### 9.3.3 INTO命令
INTO命令は、OFフラグの状態に応じてソフトウェア割込みを発生させる命令である。
OFフラグが1の場合、割込み番号04hのソフトウェア割込みを発生させる。
OFフラグが0の場合、割込みは発生せず、次の命令へ進む。
INTO命令による割込みでは、INTO命令の次の命令のアドレスを復帰先IPとして保存する。

## 9.4 ハードウェア割込み
ハードウェア割込みは、外部装置または外部回路からの割込み要求によって発生する割込みである。
AS116では、ハードウェア割込みを以下の2種類に分類する。

### 9.4.1 NMI（マスク不可能割込み）
NMIは、FLAGSレジスタのIFフラグによるマスクの影響を受けない割込みである。
NMIには割込みベクタ `02h` を割り当てる。

### 9.4.2 マスク可能割込み
マスク可能割込みは、FLAGSレジスタのIFフラグによって受け付けを制御できる割込みである。
IFフラグが1の場合に割込み要求を受け付け、0の場合は受け付けない。
マスク可能割込みのベクタ番号は、外部の割込み制御回路から供給されるものとする。割込み制御回路の詳細および外部インターフェースについては、本仕様の対象外とする。
ハードウェア割込みは、実行中の命令が完了した後に処理される。保存する復帰先IPは、完了した命令の次の命令のアドレスとする。

## 9.5 シングルステップ割込み
シングルステップ割込みは、FLAGSレジスタのTFフラグによって制御される割込みである。
TFフラグが1の場合、命令の実行が完了するごとにシングルステップ割込みを発生させる。
シングルステップ割込みには割込みベクタ `01h` を割り当てる。
シングルステップ割込みが発生した場合、実行が完了した命令の次の命令のアドレスを復帰先IPとして保存する。

## 9.6 割込み処理
割込みが受け付けられると、CPUは以下の順序で処理を行う。
1. FLAGSレジスタの値をスタックに保存する。
2. IFフラグおよびTFフラグを0にする。
3. CSレジスタの値をスタックに保存する。
4. 割込みまたは例外の種類に応じた復帰先IPをスタックに保存する。
5. 割込みベクタテーブルから対応するIPおよびCSを読み出す。
6. 読み出した値をIPレジスタおよびCSレジスタに設定する。
7. 割込みハンドラの実行を開始する。

復帰先IPの値は、割込みまたは例外の種類に応じて決定する。各割込みおよび例外における復帰先IPについては、本章および第10章の規定に従う。
スタックへの保存にはSSおよびSPを使用する。スタック操作の詳細については第8章を参照すること。

## 9.7 割込みからの復帰
割込みハンドラの処理を終了し、割込み前の処理へ復帰する場合はIRET命令を使用する。
IRET命令は、スタックから以下の順序で値を復元する。

1. IPレジスタ
2. CSレジスタ
3. FLAGSレジスタ

これにより、割込み発生前の実行位置およびFLAGSレジスタの状態が復元され、保存された復帰先IPから処理を再開する。

## 9.8 割込み優先順位
複数の割込み要求または割込み要因が同時に存在する場合、AS116では以下の優先順位に従って処理する。
| 優先順位 | 割込み・例外 |
|---:|---|
| 1（最高） | #DE、ソフトウェア割込み（INT、INT3、INTO） |
| 2 | #UD |
| 3 | NMI |
| 4 | マスク可能割込み |
| 5（最低） | シングルステップ割込み |

優先順位の高い割込みまたは例外を先に処理する。優先順位の低い割込み要求は、優先順位の高い割込みまたは例外の処理後、受け付け条件を満たす場合に処理する。
マスク可能割込みは、上記の優先順位に加え、IFフラグが1である場合にのみ受け付ける。

# 10　例外

## 10.1 例外概要
例外は、CPUの命令実行中に特定の条件が発生した場合に、CPUが発生させる割り込みである。
AS116では、例外の発生時に対応する例外ベクタを使用して例外処理へ移行する。
例外処理における割り込みベクタテーブル（IVT）の参照およびスタック操作については、第9章の規定に従う。

## 10.2 例外一覧
AS116では、以下の例外を定義する。
| ベクタ番号 | 例外名 | 概要 |
|---:|---|---|
| 00h | #DE | 除算エラー |
| 06h | #UD | 未定義命令および無効な命令指定 |

各例外の発生条件については、以下の節で規定する。

## 10.3 #DE例外
#DE例外は、除算命令の実行中に除算エラーが発生した場合に発生する例外である。
本例外は、以下の場合に発生する。
- DIV命令またはIDIV命令において、除数が0である場合。
- DIV命令において、除算結果の商が格納先のビット幅で表現可能な符号なし整数の範囲を超える場合。
- IDIV命令において、除算結果の商が格納先のビット幅で表現可能な符号付き整数の範囲を超える場合。

商の格納先が8bitの場合、符号なし整数では0～255、符号付き整数では-128～127の範囲を有効とする。
商の格納先が16bitの場合、符号なし整数では0～65535、符号付き整数では-32768～32767の範囲を有効とする。
本例外が発生した場合、INT 00hに対応する例外処理へ移行する。
#DE例外では、例外を発生させたDIV命令またはIDIV命令の次の命令のアドレスを復帰先IPとして保存する。
したがって、IRET命令によって復帰した場合、例外を発生させた除算命令は再実行されず、その次の命令から処理を再開する。

## 10.4 #UD例外
#UD例外は、未定義命令の実行、または命令の指定がAS116の仕様に違反している場合に発生する例外である。
本例外は、以下の場合に発生する。
- 未定義命令(MIDがReservedとして定義された命令,定義されていないMKなど)を実行した場合。
- 無効なレジスタ識別子を指定した場合。
- レジスタ識別子において、ビット幅指定フラグと上位・下位指定フラグの組み合わせが無効である場合。
- DLとレジスタ識別子のビット幅指定が一致しない場合。
- PUSH命令またはPOP命令において、DLが0である場合。
- Jcc命令において、未定義のJcc Typeを指定した場合。
- メモリアクセス先の物理アドレスが、実装されているメモリの範囲外である場合。
- 各命令の命令コード一覧に定義されていないオペランド形式、DLおよびIMM8の組み合わせを指定した場合。

#UD例外では、例外を発生させた命令の先頭アドレスを復帰先として保存する。
したがって、IRET命令によって復帰した場合、例外を発生させた命令の先頭から処理を再開する。
なお、予約領域の値が0以外であること自体は、本例外の発生条件に含まれない。予約領域の取り扱いについては、第2.9節の規定に従う。
また、繰返し指定フラグの使用条件に反する指定については、CPUが検知できないため、本例外は発生しない。

# 11　入出力

## 11.1 入出力概要
AS116は、メモリ空間とは独立した入出力空間を持つ。
入出力空間へのアクセスには、専用命令であるINおよびOUTを使用する。
IN命令は、指定された入出力ポートからデータを読み込み、レジスタに格納する。
OUT命令は、レジスタのデータを指定された入出力ポートへ出力する。
入出力空間へのアクセスは、通常のメモリアドレッシングとは独立して行われる。

## 11.2 入出力アドレス空間
入出力空間は16bitのアドレスによって構成され、以下の範囲を持つ。
- 最小アドレス：0000h
- 最大アドレス：FFFFh

入出力空間はメモリ空間とは独立している。
そのため、メモリアドレスと入出力ポートアドレスが同じ数値であっても、それぞれ別のアドレスとして扱われる。

## 11.3 入出力命令
入出力空間へのアクセスには、Type-A命令に定義されているINおよびOUTを使用する。
IN命令は、指定された入出力ポートからデータを読み込み、指定されたレジスタに格納する。
OUT命令は、指定されたレジスタのデータを入出力ポートへ出力する。
命令のオペランド構成および命令形式については、第4章から第6章の規定に従う。

## 11.4 入出力データ幅
入出力命令で扱うデータのビット幅は、命令ヘッダのDLフィールドによって指定する。
| DL | データ幅 |
|---|---|
| 0 | 8bit |
| 1 | 16bit |

IN命令では読み込み先レジスタ、OUT命令では出力元レジスタのビット幅に従ってデータを転送する。
レジスタのビット幅とDLの指定が一致しない場合の動作については、第10章の例外仕様に従う。

## 11.6 未定義ポートの動作
機能が割り当てられていない入出力ポートを未定義ポートとして扱う。
未定義ポートに対してIN命令を実行した場合、読み込み値として00hまたは0000hを返す。
未定義ポートに対してOUT命令を実行した場合、出力されたデータは無視される。
未定義ポートへのアクセスによって例外は発生しない。

# 12　メモリマップ

## 12.1 メモリマップ概要
本章では、AS116における物理メモリ空間の構成および各メモリ領域の配置について定義する。
AS116では、記憶域を以下の3種類に分類する。
- メモリ
- BIOS EEPROM
- 補助記憶装置

これらはそれぞれ独立した記憶域であり、互いに異なるものとして扱う。
本章では、このうちCPUのメモリアドレッシングによってアクセスするメモリ空間について定義する。
割り込みベクタテーブル、BIOS実行コード領域およびVRAMは、いずれもメモリ空間内に配置される。

## 12.2 記憶域の構成
メモリ、BIOS EEPROMおよび補助記憶装置は、それぞれ独立した記憶域である。
BIOS EEPROMおよび補助記憶装置は、CPUの物理メモリアドレス空間には含まれない。
BIOS EEPROMに格納されたBIOS実行コードは、通常、BIOS EEPROMから読み出され、メモリ上の所定の領域へ書き込まれる。
補助記憶装置の構成およびアクセス方式については、本章では規定しない。

## 12.3 割り込みベクタテーブル 
割り込みベクタテーブル（IVT）は、物理アドレス `00000000h` から配置される。
IVTの領域は以下のとおりとする。
| 項目 | 値 |
|---|---|
| 開始アドレス | `00000000h` |
| 終了アドレス | `000003FFh` |
| 容量 | 1,024バイト |
| エントリ数 | 256 |
| 1エントリのサイズ | 4バイト |

各エントリの開始アドレスは、割り込みベクタ番号に4を乗算した値とする。
各エントリには、対応する割り込み処理のIPおよびCSを格納する。格納順序および各フィールドの配置は以下のとおりとする。
| エントリ内オフセット | 内容 |
|---|---|
| +0 | IP 下位8bit |
| +1 | IP 上位8bit |
| +2 | CS 下位8bit |
| +3 | CS 上位8bit |

IPおよびCSは、それぞれ16bitの値としてリトルエンディアンで格納する。
割り込みベクタテーブルの使用方法については、第9章の規定に従う。

## 12.4 BIOS実行コード領域
BIOSの実行コードは、物理アドレス `000F0000h`（`000F:0000`）からメモリ上に配置される。
通常、この領域にはBIOS EEPROMから読み出したBIOS実行コードが、そのまま書き込まれる。
BIOS EEPROM自体はメモリ空間とは独立しており、CPUはメモリ上に配置されたBIOS実行コードを実行する。
BIOS実行コード領域の容量および終了アドレスについては、BIOSの実装に依存する。

## 12.5 VRAM領域
VRAMは、メモリ空間内にマッピングされる。
VRAMの開始アドレス、容量および配置はBIOSによって定義されるため、AS116では固定のアドレスを規定しない。
VRAMの具体的な構成およびアクセス方法については、BIOSおよび各機能の仕様書で規定する。

## 12.6 未実装メモリ領域
物理アドレス空間のうち、実際にメモリが実装されていない領域を未実装メモリ領域として扱う。
未実装メモリ領域に対する読み込みまたは書き込みを行った場合、#UDを発生させる。
未実装メモリ領域の具体的な範囲は、メモリの実装構成に依存する。
なお、物理アドレスの生成可能範囲と、実際にメモリが実装されている範囲は異なるものとする。

# 13　リセット

## 13.1 リセット概要
リセットは、CPUの動作状態を初期化し、所定のアドレスから命令の実行を開始するための処理である。
AS116では、リセット時に各レジスタを所定の値に初期化する。
リセット完了後、CPUはリセットベクタから命令のフェッチを開始する。

## 13.2 リセット時のレジスタ状態
リセット時の各レジスタの値は以下のとおりとする。
| レジスタ | 初期値 |
|---|---|
| AX | 未定義 |
| BX | 未定義 |
| CX | 未定義 |
| DX | 未定義 |
| SI | 未定義 |
| DI | 未定義 |
| BP | 未定義 |
| SP | 未定義 |
| CS | `F000h` |
| DS | `0000h` |
| ES | `0000h` |
| SS | `0000h` |
| IP | `0000h` |
| FLAGS | `0000h` |

未定義とされたレジスタの値は保証されず、リセット後の値を前提としたプログラムの動作は保証されない。

## 13.3 リセットベクタ
リセット時のCSおよびIPは、それぞれ `F000h` および `0000h` とする。
したがって、リセット後の最初の命令フェッチは、以下の物理アドレスから開始される。
| 項目 | 値 |
|---|---|
| CS | `F000h` |
| IP | `0000h` |
| 物理アドレス | `000F0000h` |

リセットベクタは、BIOS実行コード領域の開始位置に対応する。

## 13.4 命令プリフェッチ
命令プリフェッチキューの有無、容量および内部構造については規定しない。これらは各マイクロアーキテクチャの実装に依存する。
リセット時には、リセット前に取得した命令データを破棄する。
リセット後の命令フェッチは、リセットベクタから開始する。
